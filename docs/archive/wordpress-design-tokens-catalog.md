# WordPress Core Design Tokens — Catalog

Verified against `/Users/davidbowman/Github/wordpress-develop` (WordPress 6.9 trunk).

WordPress runs **three coexisting token systems**, in order of newness:

1. **`@wordpress/theme` package** — new design system, `--wpds-*` CSS custom properties (autogenerated by Terrazzo). Future direction.
2. **`@wordpress/components` package** — `--wp-components-*` and `--wp-admin-theme-color*` CSS custom properties. Used by block + site editor and increasingly wp-admin.
3. **wp-admin SCSS** — legacy `$variable` SCSS tokens compiled to static values. Per-scheme color overrides via 9 admin color schemes. Dominant in PHP admin pages (Dashboard, Posts list, Plugins, etc).

Plus a fourth de-facto layer: hardcoded hex values in `common.css` that act as tokens despite never being centrally declared.

### Density variants
Selector `[data-wpds-theme-provider-id][data-wpds-density={default|compact|comfortable}]` redefines all 14 gap+padding tokens. Compact tightens (e.g. `gap-lg: 12px`), comfortable loosens (e.g. `gap-lg: 20px`).

### No dark-mode variants
No `.is-dark` class, no `prefers-color-scheme` query. Dark scheme not yet implemented in `theme/style.css`.

## 2. `@wordpress/components` package — `--wp-components-*` + `--wp-admin-theme-color*`

Source: `src/wp-includes/css/dist/components/style.css` (also `base-styles/admin-schemes.css` for the per-scheme overrides).

### Root tokens (defined at `:root`)
```css
--wp-admin-theme-color: #3858e9;
--wp-admin-theme-color--rgb: 56, 88, 233;
--wp-admin-theme-color-darker-10: rgb(33.04, 68.73, 230.46);
```

### Component-namespace tokens (referenced via fallback chain)
| Token | Default fallback |
|---|---|
| `--wp-components-color-accent` | `var(--wp-admin-theme-color, #3858e9)` |
| `--wp-components-color-accent-darker-10` | `var(--wp-admin-theme-color-darker-10, ...)` |
| `--wp-components-color-accent-darker-20` | `var(--wp-admin-theme-color-darker-20, ...)` |
| `--wp-components-color-accent-inverted` | (referenced; expected `#fff`) |
| `--wp-components-color-background` | `#fff` |
| `--wp-components-color-foreground` | `#1e1e1e` |
| `--wp-components-color-foreground-inverted` | (referenced) |
| `--wp-components-color-gray-600` | `#949494` |
| `--wp-components-color-gray-700` | `#757575` |
| `--wp-components-color-gray-800` | `#2f2f2f` |

Pattern is a 3-level fallback: `var(--wp-components-color-accent, var(--wp-admin-theme-color, #3858e9))`. Set the `--wp-components-*` token at any selector to reskin a subtree without touching admin-scheme vars.

### Destructive override
`.components-button.is-destructive` overrides `--wp-components-color-accent` to `#cc1818` plus computed `darker-10` / `darker-20`. Same shape as the brand-accent variables.

### Other referenced

### Mixins (`_mixins.scss`)

Button mixins consume only the CSS-custom-property surface so theme switching works without recompile:

- `@mixin button()` — primary; uses `var(--wp-admin-theme-color)` / `-darker-10` / `-darker-20`

- `@mixin button-tertiary()` — neutral; `#949494` border, `#1e1e1e` text, no theme color

## Migration trajectory (observed)

1. **Components/blocks editor** runs primarily on `--wp-components-*` and `--wp-admin-theme-color*` today.
2. **`@wordpress/theme` (`--wpds-*`)** is the future canonical layer — naming follows a `bg | fg | stroke` × `interactive | surface | content | thumb | track` × `brand | neutral | error | info | success | warning | caution` × `weak | normal | strong` × `default | active | disabled` matrix. Once components consume `--wpds-*` directly, the `--wp-components-*` shim collapses.
3. **wp-admin** legacy SCSS will likely keep its `$variable` system for the per-scheme palette (it works and supports 9 schemes) but the static `_tokens.scss` layer is positioned to be replaced by `--wpds-*` consumption.
4. **`common.css` hardcodes** are technical debt — each new release migrates a few more sites to either `--wp-admin-theme-color` (for brand-tinted UI) or to SCSS variables (for chrome).
